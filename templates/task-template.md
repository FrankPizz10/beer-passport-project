# Task Template

Copy this file into `issues/NNN-short-slug.md` and fill it in.

## Objective and problem statement

What needs to be done and why. One or two paragraphs.

## Evidence and current behavior

What the code does today: file paths, observed behavior, links to the relevant source. Distinguish verified facts from hypotheses.

## Scope and non-goals

What is in scope. What is explicitly out of scope.

## Affected repositories

List each repository and what changes there.

## Dependencies and risks

What must happen first. What could go wrong. What is still unknown.

## Proposed approach

Concrete steps, in order. Name the files and components involved.

## Acceptance criteria

Checkable conditions that define "done." Each one must be verifiable by a person or a test, not a matter of opinion.

## Test plan

Which tests to run or add, and what results are expected. Report exactly which tests passed, failed, or were not run.

## Documentation updates

Which hub documents change as a result (roadmap item, architecture, decisions, current state), and what the update says.
